链接器全流程：Linux x86_64 Hello World 案例

  这个案例涉及两个目标文件被链接成一个可执行文件：

  glue.asm  ──汇编──→  glue.oj     ┐
                                   ├── 链接器 ──→ hello.oj ──→ hello (ELF可执行文件)
  hello.c3 + io.c3 + bsp.c3 ──→  rest.oj    ┘

  先看两个输入文件

  文件1：glue.asm — 汇编写的启动代码：

  global main_main      ; 声明外部符号 (由 C3 代码定义)
  global bsp_exit       ; 声明外部符号

  global start          ; 定义入口点
  start:
      call main_main    ; 调用 C3 的 main 函数
      call bsp_exit     ; 调用退出函数

  global bsp_syscall    ; 定义系统调用包装
  bsp_syscall:
      mov rax, rdi
      mov rdi, rsi
      mov rsi, rdx
      mov rdx, rcx
      syscall
      ret

  文件2： C3 代码编译的 rest.oj，定义了 main_main 和 bsp_exit，引用了 bsp_syscall。

  目标文件内部结构

  汇编/编译产出的 ObjectFile 包含三样东西：

  ObjectFile (obj)
  ├── Section[]          ← 节，存放原始二进制数据（代码、数据等）
  │   ├── Section("code")  .data = [0xE8, 0x00, 0x00, 0x00, 0x00, ...]  ← call 指令带 0 占位
  │   └── Section("data")  .data = [...]
  ├── Symbol[]           ← 符号表，记录每个符号的名字、绑定、所在节、偏移
  │   ├── Symbol("start",   binding=global, section="code", value=0, defined=true)
  │   ├── Symbol("main_main", binding=global, section=null, value=null, defined=false)  ← 未定义!
  │   └── ...
  └── RelocationEntry[]  ← 重定位表，记录"哪个位置需要修正为哪个符号的地址"
      └── RelocationEntry(reloc_type=rel32, symbol_id=main_main, section="code", offset=1)

  关键：汇编器在遇到 call main_main 时，不知道 main_main 的最终地址，所以先在 call 指令的操作数位置填入
  0，同时创建一条重定位记录："等链接时把这 4 字节修正为 main_main 的地址（相对跳转）"。

  ---
  链接器的四步工作流

  入口 linker.py:100 link()，核心流程：

  merge_objects()  →  layout_sections()  →  do_relaxations()  →  do_relocations()
     ①合并           ②布局               ③松弛              ④重定位

  第一步：合并对象 (merge_objects, linker.py:193)

  把所有输入目标文件的节合并到一个输出文件中。

  def inject_object(self, obj, debug):       # linker.py:199
      section_offsets = {}

      # 1. 逐节合并
      for input_section in obj.sections:     # linker.py:204
          output_section = self.dst.get_section(input_section.name, create=True)
          # glue.oj 的 "code" 节 → 输出 "code" 节
          # rest.oj 的 "code" 节 → 也是输出 "code" 节 （追加在后面！）

          # 对齐处理
          while output_section.size % input_section.alignment != 0:
              output_section.add_data(bytes([0]))   # 填充 0 到对齐

          offset = output_section.size  # 记录当前偏移
          section_offsets[input_section.name] = offset
          output_section.add_data(input_section.data)  # 直接拼接字节！

  用图来表示：

  glue.oj   code节: [E8 00 00 00 00] [E8 00 00 00 00] [...]  ← call main_main; call bsp_exit
  rest.oj   code节: [... main_main的代码 ...] [... bsp_exit的代码 ...]

  合并后输出 code节:
  ┌─────────────────────────────────┬──────────────────────────────┐
  │  glue.oj 的 code (offset=0)     │  rest.oj 的 code (offset=..) │
  │  call main_main (占位0)         │  main_main 的代码在这里!      │
  │  call bsp_exit  (占位0)         │  bsp_exit 的代码在这里!       │
  └─────────────────────────────────┴──────────────────────────────┘

  第二步：符号解析

  继续 inject_object：

      # 2. 合并符号表 (linker.py:229)
      for symbol in obj.symbols:
          if symbol.defined:
              # 符号的值 = 节的偏移 + 符号在节内的偏移
              value = section_offsets[symbol.section] + symbol.value
              section = symbol.section
          else:
              value = section = None      # 未定义符号暂不赋值

          if symbol.binding == "global":
              new_symbol = self.merge_global_symbol(...)  # 全局符号合并
          else:
              new_symbol = self.inject_symbol(...)         # 局部符号直接插入

  merge_global_symbol (linker.py:281) 处理全局符号的定义/引用合并：

  def merge_global_symbol(self, name, section, value, typ, size):
      if self.dst.has_symbol(name):              # 符号已经存在（之前被引用过）
          new_symbol = self.dst.get_symbol(name)
          if value is not None:                  # 这次是定义它
              if new_symbol.undefined:           # 之前是未定义的引用
                  new_symbol.value = value       # → 填上真正的值！
                  new_symbol.section = section
              else:
                  raise CompilerError(f"Multiple defined symbol: {name}")
      else:
          new_symbol = self.inject_symbol(...)   # 首次出现，创建符号

      return new_symbol

  具体到我们的例子：

  处理 glue.oj 的符号:
    "start"     → inject_symbol()  → Symbol(start,    global, section=code, value=0)
    "main_main" → inject_symbol()  → Symbol(main_main, global, section=null, value=null)  ← 未定义!
    "bsp_exit"  → inject_symbol()  → Symbol(bsp_exit,  global, section=null, value=null)  ← 未定义!

  处理 rest.oj 的符号:
    "main_main" → has_symbol("main_main")=True → merge_global_symbol()
                  之前 value=null (未定义), 这次有值 → 填上: value=0x30, section=code
    "bsp_exit"  → 同理，填上: value=0x80, section=code

  合并后的符号表：

  输出 ObjectFile 的符号表:
  ┌───────────────┬─────────┬─────────┬──────────┬─────────┐
  │ Name          │ Binding │ Defined │ Section  │ Value   │
  ├───────────────┼─────────┼─────────┼──────────┼─────────┤
  │ start         │ global  │ yes     │ code     │ 0x00    │ ← glue.oj 定义
  │ main_main     │ global  │ yes     │ code     │ 0x30    │ ← rest.oj 定义，解析完成
  │ bsp_exit      │ global  │ yes     │ code     │ 0x80    │ ← rest.oj 定义，解析完成
  │ bsp_syscall   │ global  │ yes     │ code     │ 0x10    │ ← glue.oj 定义

  glue.oj 中 call main_main 在 code 节的 offset=1 处，现在 glue.oj 的 code 节被放在输出的 offset=0，所以重定位位置不变：offset = 0 + 1 =
  1。

  第二步：布局 (layout_sections, linker.py:309)

  链接脚本 linux64.mmap：

  MEMORY code LOCATION=0x40000 SIZE=0x10000 {
      SECTION(code)
  }
  MEMORY ram LOCATION=0x20000000 SIZE=0xA000 {
      SECTION(data)
  }

  layout_sections 根据这个脚本给每个节分配最终的内存地址：

  def layout_sections(self, layout):
      for mem in layout.memories:                        # MEMORY code ...
          image = Image(mem.name, mem.location)          # Image("code", 0x40000)
          current_address = mem.location                 # current = 0x40000

          for memory_input in mem.inputs:                # SECTION(code)
              section = self.dst.get_section("code")
              # 对齐
              while current_address % section.alignment != 0:
                  current_address += 1
              section.address = current_address          # ← code节的地址 = 0x40000
              current_address += section.size
              image.add_section(section)

  效果：输出文件的 code 节被放在地址 0x40000，data 节放在 0x20000000。现在每个字节都有了自己的运行时地址。

  第三步：链接器松弛 (do_relaxations, linker.py:426)

  某些跳转指令有"短版本"和"长版本"。编译时保守生成长版本，链接时发现目标很近，就替换为短版本。

  例如:  jmp far_label     → 原来 5 字节 (E9 + 32位偏移)
        发现 far_label 只有 50 字节远
        → 替换为 2 字节 (EB + 8位偏移)

  第四步：重定位 (do_relocations, linker.py:615)

  这是链接器的核心操作——把占位 0 修改为正确的地址值。

  def _do_relocation(self, relocation):
      sym_value = self.get_symbol_value(relocation.symbol_id)  # main_main 的运行时地址
      section = self.dst.get_section(relocation.section)       # code 节
      reloc_value = section.address + relocation.offset        # call 指令操作数的运行时地址

      # 构造架构相关的重定位对象
      rcls = self.dst.arch.isa.relocation_map[relocation.reloc_type]
      reloc = rcls(None, offset=relocation.offset, addend=relocation.addend)

      # 读取原始字节 → 计算新值 → 写回
      data = section.data[begin:end]
      data = reloc.apply(sym_value, data, reloc_value)
      section.data[begin:end] = data

  具体例子 — call main_main：

  x86_64 的 call 指令使用相对偏移：call 的目标 = 下一条指令地址 + 偏移量。

  Rel32JmpRelocation (instructions.py:155)：

  class Rel32JmpRelocation(Relocation):
      name = "rel32"

      def calc(self, sym_value, reloc_value):
          # 相对偏移 = 目标地址 - 重定位位置 - 指令长度
          return sym_value - reloc_value - 4

      def apply(self, sym_value, data, reloc_value):
          offset = self.calc(sym_value, reloc_value)
          # 构建一个 Imm32Token，把 offset 编码到 token 的 field 中
          token = self.token.from_data(data)   # 解析原始 4 字节
          token.set_field(self.field, offset)  # 把计算好的偏移写入
          return token.encode()                # 编码回 4 字节

  代入实际数值：

  原始状态 (glue.oj 汇编时):
    call main_main  →  E8 00 00 00 00     (偏移=0, 占位)

  链接时:
    code节地址 = 0x40000
    call指令操作数在 code+1 → reloc_value = 0x40001
    main_main 的符号值 = 0x40000 + 0x30 = 0x40030  (code节基址 + main_main在节内偏移)

    offset = sym_value - reloc_value - 4
           = 0x40030 - 0x40001 - 4
           = 0x2B

    最终: E8 2B 00 00 00

  用一张图展示整个重定位过程：

  链接前 (glue.oj 的 code 节):
    E8 00 00 00 00           ← call 的操作数 = 0 (不知道 main_main 在哪)
    ^^
    操作码

  链接后 (输出 hello.oj 的 code 节, 地址 0x40000):
    E8 2B 00 00 00           ← call 的操作数 = 0x2B = main_main(0x40030) - 下条指令(0x40005)
    ^^  ^^^^^^^^^
        main_main 的相对偏移

    0x40000: E8 2B 00 00 00  ← call main_main → 跳转到 0x40005 + 0x2B = 0x40030 ✓
    0x40005: E8 xx xx xx xx  ← call bsp_exit
    ...
    0x40030: ...              ← main_main 的代码在这里!
    ...
    0x40080: ...              ← bsp_exit 的代码在这里!

  ---
  总结：链接器的五步全貌

  输入: glue.oj + rest.oj                   输入: linux64.mmap
    │ Section[], Symbol[], Reloc[]              │ MEMORY code LOCATION=0x40000...
    │                                          │
    ▼                                          ▼
  ①merge_objects()                        ②layout_sections()
    - 拼接同名节 (code+code, data+data)        - 给每个节分配运行时内存地址
    - 合并符号表 (未定义→定义，解决引用)          - code → 0x40000
    - 调整重定位偏移 (加上节在合并节中的offset)    - data → 0x20000000
    │                                          │
    ▼                                          │
  ③do_relaxations()                          │
    - 短跳转优化 (5字节→2字节)                   │
    - 更新所有符号和重定位偏移                    │
    │                                          │
    ▼                                          ▼
  ④do_relocations()
    - 对每条重定位记录:
      1. 查符号的最终地址
      2. 计算当前位置的运行时地址
      3. 根据重定位类型计算修正值 (相对/绝对)
      4. 把修正值写入节数据的对应位置 (hammer the bits!)
    │
    ▼
  ⑤check_undefined_symbols() → 报错 or 通过
    │
    ▼
  输出: ObjectFile (一个完整的、所有地址都已解析的、可被 objcopy 转成 ELF/HEX 的文件)

  链接器的本质工作就是一句话：把多个目标文件的节拼在一起，把符号的"占位 0"替换成真正的地址。这和 C
  语言经典教材中描述的链接器完全一致，只是 qcc 用 ~650 行 Python 把它实现得清晰可读。
